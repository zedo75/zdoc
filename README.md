## 这是什么

**一套基础设施 + 一个开箱即用的应用：**

- 🧩 **`vite-plugin-wps-enhance`** —— Vite 插件，把 WPS 加载项从"手写 XML + 魔法数字 + 无法测试"升级到前端工程化水平
- 📝 **`zdoc`** —— 基于此插件构建的公文排版工作台：一键排版、批量处理、活文档对比、邮件合并增强……

> 如果你只想要"又一个公文助手"，市面上有很多。
> 如果你想找**工程化程度、可测试性、二次排版速度**都到位的方案，继续往下读。

## 为什么不是又一个"公文助手"

### 与传统 WPS 加载项开发方式的对比

| 维度             | 传统方式（VBA / 手写 XML / 裸 JSA）       | 本项目                                                     |
| ---------------- | ----------------------------------------- | ---------------------------------------------------------- |
| **Ribbon 定义**  | 手写数百行 XML，改按钮要同步改 XML + 绑定 | TypeScript 函数式 API，自动渲染 XML                        |
| **控件回调**     | 控件 `id` 是裸字符串，拼错只能运行时崩    | 自动生成 `RibbonControlId` **联合类型**，编译期校验        |
| **枚举常量**     | 必须 `wps.Enum.xxx` 或裸写魔法数字        | 源码里写 `wdAlignParagraphCenter` 就够，**构建时按需生成** |
| **图片图标**     | 手写路径字符串，改名/删图即时崩           | 扫描目录生成 `ImageFileName` 类型，**路径由 TS 保证**      |
| **排版逻辑测试** | 必须开 WPS 人工点按钮观察                 | **纯文本输入 → vitest 断言**，CI 可跑                      |
| **排版速度**     | 全量重设每个属性，二次排版与首次一样慢    | **差异计算**：已排好的段落一条指令都不发，二次排版接近瞬时 |
| **新增段落样式** | 分散在 3~5 个函数里的 if/else             | `ATTRS` 数组加一项，核心遍历代码零改动                     |
| **dev 二次启动** | 每次重扫 `.d.ts` 枚举库                   | 三级缓存（内存→落盘→实扫），**命中 <1ms**                  |
| **弹窗冷启动**   | 拉起完整应用                              | URL 分流：`?dialog=xxx` 只加载 Vue + 单组件，**≈500ms**    |

### 一个具体例子

**传统方式**：给"落款日期"加一条左对齐规则，你要在排版函数、样式应用、差异检测三个地方同时改。

**本项目**：打开 `src/core/attributes.ts`，在 `ATTRS` 数组加一项：

```ts
{
    key: "alignment",
    desired(p) {
        if (p.semanticKinds.has("signatureDate")) return wdAlignParagraphLeft;
        return undefined;
    },
    readCom: (rng) => rng.ParagraphFormat.Alignment,
    isEqual: (a, b) => a === b,
    apply: (rng, v) => { rng.ParagraphFormat.Alignment = v; },
}
```

差异计算、应用修改、属性合并全部自动生效——**并且自带单测能力**。

## 功能速览

> 完整操作说明见 [功能手册](./FEATURES.md)

### 🚀 核心能力

| 模块              | 一句话                                                                      |
| ----------------- | --------------------------------------------------------------------------- |
| **一键排版**      | 标题/正文/层级/抬头/附件/落款全自动识别 + 应用样式，**二次排版近似瞬时**    |
| **活文档对比**    | 在文档里标记一段文字，之后编辑这段文字，对比框**实时同步**                  |
| **批量排版**      | 拖入多个 docx，进度条 + 时间戳日志，单个失败不影响其他                      |
| **快捷样式弹窗**  | 选中文本→点按钮，**弹窗秒开**（不加载主应用）                               |
| **邮件合并增强**  | Excel 扁平数据 + row/group 循环 + #if，正文/表格/页眉占位符，真实 DOCX 预览 |
| **页面设置**      | 六项边距 + 页眉 + 页脚，全部支持鼠标滚轮调值                                |
| **全半角 / 标点** | 英文标点转全角、字母数字转半角、引号配对更正                                |

### 📋 页面设置面板

四个可折叠区（页面 / 字体 / 页眉 / 页脚），独立应用或一键「应用所有设置」。

- **页眉**带密级预设：内部★注意保管 / 秘密★1年 / 机密★5年 / 绝密★长期
- **页脚**页码 **5 种位置**（内侧/外侧/左/中/右）带位置示意图
- **字体**联动：改中文字体，西文字体若选「随中文」自动跟随
- **状态提示**：切换文档时页脚自动刷新「已设置 / 未检测到页码」

## 典型工作流

### 场景一：新收一份公文，一键排版

1. 打开文档
2. Ribbon → 快速排版 → 完成
3. 标题、正文、层级标题、抬头、附件、落款全部识别并套用样式

**再排一次几乎是瞬时的**——差异计算只对确实不一致的段落下发指令。

### 场景二：修改一稿，看看改了哪里

1. Ribbon → 文本对比 → 打开任务窗格
2. 在文档里**选中原始文字** → 点击「📌 标记选区段落」
3. 切到「旧文本」记为原稿，再切到「新文本」，随手编辑文档
4. 对比框**实时显示改动**——无需先保存两份文件

### 场景三：领导下发 20 个文件，统一格式

1. Ribbon → 批量排版
2. 选择 20 个 docx
3. 点「开始批量排版」，进度条 + 每条的日志（成功绿/失败红）
4. 单个文档打开失败不影响其他

### 场景四：编辑文档时右栏需要看到合并域

1. Ribbon → 邮件合并 → 插入合并域
2. **鼠标移入面板时自动拉取最新字段列表**（在文档里改了表头，回来立刻是新的）
3. 单击字段标签 → 插入到光标位置
4. 顶部可直接输入记录号跳转 + 切换「显示值 / 显示域」+ 调整域底纹

### 场景五：Excel 邮件合并

1. 在模板文档里写 `{{姓名}}`、`{{金额 | "0.00"}}` 等占位符
2. 用 `{{#each row in:E..T cols:4 as:姓名,关系,单位,电话}}` 横向展开一行中的多组数据
3. Ribbon → 邮件合并，选择 `.xlsx` / `.xls` / `.et`
4. 选表头行、记录范围（全部 / A..B / 单条）
5. 先「预览所选」检查真实 WPS 排版，再「开始合并」

详细语法、group 分组和 `#if` 见 [FEATURES.md](./FEATURES.md#邮件合并excel-批量)。

## 架构一句话

```text
┌─────────────────────────────────────────────────┐
│  功能层：插件                                    │
│  src/features/<插件>/ → 一个目录 = 一个功能       │
├─────────────────────────────────────────────────┤
│  插件内核：契约 / 功能区装配 / 派发               │
│  src/kernel/ → 新增功能只改插件目录 + 两行注册    │
├─────────────────────────────────────────────────┤
│  纯逻辑层（可单测）                              │
│  core/analysis.ts → 语义识别（15 种段落类型）     │
├─────────────────────────────────────────────────┤
│  属性注册表 + 差异计算                           │
│  core/attributes.ts → 新增属性=加一行             │
├─────────────────────────────────────────────────┤
│  COM 编排（唯一触碰 Wps.* 的排版模块）           │
│  core/pipeline.ts → 批量读段 / 缓存 / 差异应用   │
└─────────────────────────────────────────────────┘
```

功能层是**插件式**的：文本对比、邮件合并、批量处理等综合性功能各自是一个 `src/features/<id>/` 目录，
通过 `src/kernel` 的契约声明 Ribbon 控件、弹窗、任务窗格与动作；插件之间不互相 import。

**完整架构设计**（插件契约、分层规则、vite-plugin-wps-enhance 原理、测试策略、扩展指南）见 [ARCHITECTURE.md](./ARCHITECTURE.md#23-插件式架构功能层)。

## 目录结构

```text
plugins/vite-plugin-wps-enhance/   构建插件（pnpm workspace，只服务工程化）
  ├── enum/                        枚举扫描 + 按需生成
  ├── ribbon/                      TS 配置 → ribbon.xml
  └── image/                       图片目录 → 文件名类型

src/
├── kernel/                        插件内核：契约 / 功能区装配 / 派发 / 图标
├── ribbon/                        宿主接入：功能区回调 + 任务窗格窗口
├── features/                      功能插件（一个目录 = 一个插件）
│   ├── gov-doc/                   公文排版 + 设置面板 + 快捷样式
│   ├── text-compare/              文本对比工作台
│   ├── mail-merge/                Excel 邮件合并
│   ├── batch/                     批量排版 / 转换 / 重命名
│   ├── format-check/              格式检查
│   ├── image-tools/               图片工具
│   ├── punctuation/               标点规则
│   ├── table/                     表格
│   └── doc-utils/                 零散文档命令（清除格式 / 缩进 / 编号）
├── core/                          排版引擎（语义识别 + 属性差异 + 公文排版编排）
├── wps/                           WPS COM 原语（文档 / 文件 / 视图 / 撤销 / 书签）
├── composables/                   通用 composable（不含业务规则）
├── components/                    通用 UI 组件
├── config/ stores/ utils/         配置、全局状态、纯工具
├── views/index.vue                任务窗格导航页
└── tests/                         引擎 / 共享工具 / 插件契约 / 分层边界测试
```

每个插件内部按需分层：`index.ts`（声明）、`ribbon.ts`（功能区）、`actions.ts`（动作）、
`commands/`（WPS 编排）、`core/`（纯逻辑）、`composables/`（业务封装）、`components/`、
`dialogs/`、`views/`、`tests/`。插件之间需要共享的能力按职责沉到 `wps/`（COM 原语）、
`core/`（排版编排）、`utils/`、`config/`，不允许插件互相 import。
详见 [ARCHITECTURE · 插件式架构](./ARCHITECTURE.md#23-插件式架构功能层)。
